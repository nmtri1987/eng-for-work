W02
WEEK 2 · 18 SEP 2026 Early adoption

Early adoption & hands-on support

Training → real PRs; support needs become visible

80%E-learning progress reported

Key message Technical teams began using the full agent sequence. For SolEx users, dedicated human help was more valuable than adding generic documentation.

◉ Key findings & evidence

  • RESULTTechnical teams started running spec → plan → implement → PR review on real tickets.
  • BLOCKERSolEx adoption required changes in working habits, dedicated coaching and confidence-building.
  • BLOCKERSome SolEx users still lacked MAIA access at the end of Week 2.
  • GUIDANCESwitch from plenary sessions to practical, team-by-team sessions.
  • OPENPR review sometimes reported issues unrelated to the ticket; complete functional-to-technical E2E was still missing.
  • OPENQuestions began about governed, project-specific agent contributions.

◇ Caveats & risks

  • Unresolved MAIA access can distort adoption results.
  • Training competes with normal project delivery.
  • Early PR activity does not prove productivity gains.

How to read the numbers: 80% reflects an e-learning progress snapshot mentioned in the transcript, not agent adoption.

✓ Follow-up from this week

  1. Resolve MAIA access and confirm users can enter the workspace.
  2. Run team-by-team SolEx support on real project examples.
  3. Collect PR-review relevancy issues and plan a representative E2E walkthrough.

W03
WEEK 3 · 25 SEP 2026 Adoption friction

Workflow fit, quality of inputs & user confidence

45–60% agentic PRs in active squads; MAIA rigidity exposed

3.8 → 3.4User confidence / satisfaction

Key message Technical adoption became measurable but uneven. The major question shifted from whether the agents run to whether workflows match real work.

◉ Key findings & evidence

  • RESULTAround 45–60% of PRs in active technical teams were being built with agents.
  • RESULTMAIA Chat and development workspace access was confirmed for functional users.
  • BLOCKEREDI Adapter lacked suitable user stories; CWSink was still preparing new-product specs and backlog.
  • BLOCKERSolEx considered MAIA too rigid; perceived productivity and confidence dropped.
  • PROPOSALNew update workflow allowed existing SPF/BRD to be updated without full regeneration.
  • OPENAgents occasionally ran very long; one PR review reportedly took about two hours; root cause unconfirmed.

◇ Caveats & risks

  • Cannot compare a mature squad with a new product using the same raw PR percentage.
  • High question volume in the functional workflow creates friction.
  • Word collaboration and user-controlled iteration were not solved yet.

How to read the numbers: 45–60% applied to active technical squads, not an organization-wide adoption rate; long runtime had no confirmed root cause.

✓ Follow-up from this week

  1. Review EDI Adapter backlog and improve story input.
  2. Help CWSink finish its first functional artifacts.
  3. Collect latency evidence before attributing slowness to network, models or agents.

“ Phrases to remember

We should not over-interpret a small change in the percentage.Không nên kết luận quá nhiều từ thay đổi phần trăm nhỏ.
The workflow feels too rigid for the users.Workflow bị cảm nhận là quá cứng nhắc.
We need to understand what is causing the delay.Cần xác định nguyên nhân gây chậm.

WEEK 4 · 02 OCT 2026 Midpoint iteration

MAIA flexibility, HLD location & governance

Word round-trip, GitHub Copilot HLD, first EDI Adapter use

~3.7Individual confidence rebound

Key message The team reacted to feedback: human-controlled editing was added to MAIA and HLD moved into the developer environment. Governance became more explicit.

◉ Key findings & evidence

  • RESULTMAIA gained Word export, offline editing and re-import without automatic AI modifications.
  • RESULTHLD agent moved into GitHub Copilot (the transcript identifies release 1.0.24).
  • RESULTEDI Adapter ran spec-driven agents for the first time after targeted support.
  • RESULTIndividual confidence rebounded to around 3.7; team-level confidence stayed weaker.
  • PROPOSALOn-site SolEx support, extra engineering capacity and visible weekly improvement backlog.
  • OPENComplete functional input → spec → development → PR end-to-end evidence was still missing.

◇ Caveats & risks

  • First use by EDI Adapter did not yet prove repeatable adoption.
  • Individual perception and measured team productivity are different.
  • Need to distinguish platform limitations from fixable agent bugs.

How to read the numbers: The HLD move and first usage were reported milestones; no full E2E proof or guaranteed impact was established.

✓ Follow-up from this week

  1. Test Word round-trip and MAIA output with representative business scenarios.
  2. Gather Tech Lead feedback on the HLD agent and architecture inputs.
  3. Publish and validate weekly backlog actions and maintain central governance for agent extensions.

W05
WEEK 5 · 09 OCT 2026 Decision pressure

First functional success & strategic MAIA question

First SPF-to-backlog example, local checks, quality / UX reassessment

3.7 → 2.6Reported confidence decrease

Key message One SolEx team generated a usable functional specification and backlog artifacts, but general confidence remained low. MAIA itself became a strategic choice.

◉ Key findings & evidence

  • RESULTOne team generated an SPF, user stories and test cases into the backlog using MAIA.
  • BLOCKERConfidence dropped sharply; an individual success did not demonstrate repeatable functional adoption.
  • PROPOSALReassess MAIA UX if output quality and usability remain below expectations; evaluate alternate UI and Copilot/Word.
  • GUIDANCEPreserve structured knowledge and downstream artifacts even if front end changes.
  • RESULTHLD scenarios without upstream SPF were recognized, including refactoring and technical migration.
  • RESULTLocal SonarQube and Snyk pre-checks were introduced to move security feedback earlier, not replace CI gates.
  • BLOCKEREDI Adapter required stronger upstream context/user-story quality for agents to produce good technical results.

◇ Caveats & risks

  • Single successful run is not a repeatable enterprise capability.
  • Model quality, workflow, context, harness and validation must be evaluated separately.
  • A full workflow is inappropriate for one-line document edits.

How to read the numbers: Confidence scores are survey self-assessments, not independently measured throughput.

✓ Follow-up from this week

  1. Compare functional outputs with the same inputs across model/workflow options.
  2. Validate small-edit and incremental user-story use cases.
  3. Build strong upstream user stories for EDI Adapter and track subsequent PR quality.

“ Phrases to remember

The tool should fit the use case, not the other way around.Công cụ phải phù hợp nhu cầu, không phải ngược lại.
One successful case is not enough to prove adoption.Một trường hợp thành công chưa đủ chứng minh adoption.
Local scans do not replace the CI quality gates.Scan local không thay thế CI quality gates.

WEEK 6 · 16 OCT 2026 Technical traction

Workflow depth, PR review & custom-agent governance

Strong technical feedback; task complexity and governance take center stage

>80%DemDet adoption (reported)

Key message Technical teams showed promising results on complex user stories. The main design principle became matching workflow depth to task size and risk.

◉ Key findings & evidence

  • RESULTTechnical-side feedback was positive, especially for complex user stories; one comparison favored AI output over manual output.
  • RESULTDemDet exceeded 80% adoption in the playbook; other teams had very different activity profiles.
  • PROPOSALSupport parallel isolated PR reviews and improve first-pass coverage.
  • GUIDANCEUse direct Copilot for tiny fixes, concise artifacts for normal changes and detailed workflow for complex work.
  • GUIDANCEFix critical/major PR findings; evaluate minor findings pragmatically instead of endlessly rerunning LLM review.
  • OPENWhether developers may create custom agents remained a governance discussion due to duplication, conflict and maintenance risk.
  • RESULTSolEx aligned on common SPF template; model, source fidelity and image-processing tests continued.

◇ Caveats & risks

  • Low xOne measured adoption was confounded by production incidents, ticket linking and low PR activity.
  • Agent extensions require versioning, guardrails and ownership.
  • Full spec/plan cost can exceed the value of a minor fix.

How to read the numbers: DemDet >80% is a period-specific reported adoption indicator, not overall Phase 1 productivity.

✓ Follow-up from this week

  1. Define lightweight/normal/full workflow decision rules.
  2. Pilot parallel PR reviews and shorten spec/plan for human review.
  3. Document a governed custom-agent contribution model and compare team KPIs fairly.

“ Phrases to remember

The workflow should match the complexity of the task.Workflow nên phù hợp độ phức tạp của task.
A lower adoption rate does not automatically mean resistance.Adoption thấp không tự động có nghĩa team phản đối.
